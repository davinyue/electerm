# GitHub 多平台构建发布

## 背景

fork 仓库继承了上游构建和发布工作流，其中包含上游仓库地址、签名凭据及外部发布任务，不能直接用于独立发布。

## 目标

使用 GitHub Actions 构建 Linux x64、Windows x64 和 macOS ARM64 安装包，全部构建成功后汇总到 fork 仓库的 Release 草稿，由用户验证后发布。

## 范围

- 手动触发多平台构建并上传构建制品。
- 构建成功后以项目版本创建草稿，避免覆盖已有标签或 Release。
- 在 fork 中阻止上游专用的商店发布和外部同步工作流运行。
- 将构建仓库指向 fork；macOS 使用未签名的测试构建。

## 非目标

- 不发布正式 Release，不配置 Apple 或 Windows 签名证书。
- 不修改应用的上游自动更新服务，也不发布到 npm 或应用商店。

## 关键设计

各平台构建时禁止 electron-builder 自动发布，使用 Actions artifacts 传递制品；单独的汇总任务检查版本、标签及 Release 后创建草稿并上传附件。

## 验收标准

- 手动触发后，三平台构建成功并生成约定格式的制品。
- 草稿及附件仅创建于 fork 仓库；已有标签和 Release 不被覆盖。
- fork 的正式 Release 不触发上游商店发布或外部同步。
- 明确未签名及自动更新仍指向上游的限制。
